# AIDX 스튜디오

수업 주소: https://ptmanagement.vercel.app/studio/

물리치료과 1학년의 15주 근골격계 질환 프로젝트를 위한 수업 공간입니다.
A반 4조, B반 5조, 조당 학생 3명을 지원합니다.
저장소 첫 화면의 기존 앱과 `/pt-exam-vercel/index.html` 환자관리 기록지는 보존합니다.

## 수업 시작

1. 교수 관리자로 로그인합니다.
2. **조별 학생 관리**에서 학생 이름·학번을 등록하고 접속 코드를 학생에게 직접 전달합니다. 접속 코드는 저장 후 조회할 수 없고 재발급할 수 있습니다.
3. **조 설정**에서 조 이름과 질환 주제를 입력합니다. 학생 로그인 시에는 기본 반·조를 선택합니다.
4. **주차별 과제 설정**에서 안내와 마감일을 수정합니다. 기본 주제는 수정 가능한 제안입니다.
5. 학생은 조·학번·접속 코드로 로그인하고 주차별 결과를 제출합니다.
6. 교수는 전체 현황표에서 제출물을 선택해 잘한 점·보완할 점·다음 주 제안을 남깁니다.

마감 이후에도 제출할 수 있으며 지연 표시가 붙습니다. 파일은 1개당 10MB, 제출당 5개까지 가능합니다.
재제출은 이전 버전을 보관합니다. 피드백은 해당 제출 버전에 연결됩니다.
두 조원이 동시에 수정하면 오래된 버전의 제출을 막습니다. 화면의 작성 내용은 제출 전에는 저장되지 않습니다.
화면 둘러보기는 가상 예시이며 실제 제출이나 피드백 저장은 할 수 없습니다.

## 첫 교수 계정 설정

현재 공개 회원가입이나 공개 관리자 생성 기능은 없습니다.
프로젝트 소유자가 Supabase 대시보드의 Authentication → Users → Add user → Create new user에서
본인의 이메일과 비밀번호를 직접 설정한 뒤, 해당 사용자를 `aidx_profiles`의 professor로 등록해야 합니다.
비밀번호나 service_role 키를 채팅 또는 GitHub에 올리지 마세요.
이 계정 설정 후 화면 상단의 **비밀번호 변경**으로 새 비밀번호를 설정할 수 있습니다.

## 구현 및 운영

- `public/studio/`: HTML/CSS/JavaScript 화면
- `server/app.js`, `lib/`: 요청 검증과 서버 기능
- `supabase/edge/index.ts`: Supabase Edge Function 어댑터
- `supabase/migrations/001_aidx.sql`: 적용된 수업 데이터 구조와 권한 규칙
- `tests/`: 입력 검증, 비로그인 차단, 데이터베이스 권한 시험
- `vercel.json`: 공개 화면 배포와 `/classroom-api` 서버 연결

서버 함수명은 `aidx-api`입니다. 배포 시 index.ts와 server/lib 파일을 상대 경로 그대로 포함해야 합니다.
로그인·공개 설정 요청만 비로그인 상태로 허용하며, 나머지는 Supabase Auth에서 사용자 토큰을 검증합니다.
일반 요청은 사용자 토큰으로 RLS를 적용합니다. service_role 키는 서버의 계정 관리에만 사용합니다.
첨부파일 저장소는 비공개이고, 본인 조 또는 교수만 짧은 만료시간의 다운로드 링크를 발급받습니다.
세션은 브라우저 탭의 sessionStorage에 저장되며 공용 PC에서는 로그아웃하세요.

로컬 실행: `npm run dev` 후 http://127.0.0.1:4325/studio/
검증: `npm test`, `npm run build`
서버 코드를 바꾸면 Supabase Edge Function도 다시 배포해야 합니다. GitHub 업로드만으로 서버는 갱신되지 않습니다.
`.env.example`은 로컬 서버 설정 안내입니다. 실제 키가 든 `.env.local`은 저장소에 올리지 않습니다.

## 검증 상태

입력 검증·비로그인 차단 단위 시험 통과. 데이터베이스 트랜잭션 시험으로 다른 조 접근 차단,
3명 정원 제한, 오래된 버전 수정 차단, 제출 이력·피드백 버전 연결, 비로그인 조회 차단을 확인했습니다.
시험 레코드는 트랜잭션을 취소해 남기지 않았습니다.
실제 교수·학생 계정으로 로그인하여 제출·파일 업로드·피드백을 수행하는 최종 확인은 첫 계정 설정 후 진행해야 합니다.
